Kairn is recording. Cluster id: {{ .Values.clusterId }}

1. Point Alertmanager at the webhook:

     receivers:
       - name: kairn
         webhook_configs:
           - url: http://{{ include "kairn.fullname" . }}-webhook.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}/webhook
             send_resolved: false
{{- if .Values.webhook.auth.enabled }}
             http_config:
               authorization:
                 credentials_file: /etc/alertmanager/secrets/kairn-webhook-token/token

   The webhook requires a bearer token. Copy it where Alertmanager can mount it, e.g.:

     kubectl -n {{ .Release.Namespace }} get secret {{ include "kairn.webhookTokenSecret" . }} -o jsonpath='{.data.token}' | base64 -d \
       | kubectl -n <alertmanager-namespace> create secret generic kairn-webhook-token --from-file=token=/dev/stdin

   (kube-prometheus-stack: list it under alertmanager.alertmanagerSpec.secrets.)
{{- if not .Values.webhook.auth.existingSecret }}
   GitOps note: tools that render with `helm template` (e.g. Argo CD) can't keep the
   generated token stable; create your own Secret (key `token`, ≥ 32 chars) and set
   webhook.auth.existingSecret.
{{- end }}
{{- else }}

   WARNING: webhook.auth.enabled=false: anything that can reach the Service can trigger captures.
{{- end }}

2. See it work without waiting for a real outage:

     kairn demo{{ if ne .Release.Namespace "kairn-system" }} --kairn-namespace {{ .Release.Namespace }}{{ end }}

3. List captures:  kubectl -n {{ .Release.Namespace }} get incidentcaptures

{{- if eq .Values.signing.mode "kms" }}

Every bundle is signed with KMS key {{ .Values.signing.kms.key }}.
  Auditors verify with the key from the KMS itself:
    kairn key fetch --kms {{ .Values.signing.kms.key }}     # writes kairn.pub
    kairn verify <bundle.ieb> --key kairn.pub
  The controller logs the key_id it pinned at startup. Captures wait in Sealing (data kept)
  while KMS is unreachable; see docs/kms.md for the IAM and key policy Kairn requires.
