Lapilli is recording. Cluster id: {{ .Values.clusterId }}

1. Point Alertmanager at the webhook:

     receivers:
       - name: lapilli
         webhook_configs:
           - url: http://{{ include "lapilli.fullname" . }}-webhook.{{ .Release.Namespace }}.svc:{{ .Values.service.port }}/webhook
             send_resolved: false
{{- if .Values.webhook.auth.enabled }}
             http_config:
               authorization:
                 credentials_file: /etc/alertmanager/secrets/lapilli-webhook-token/token

   The webhook requires a bearer token. Copy it where Alertmanager can mount it, e.g.:

     kubectl -n {{ .Release.Namespace }} get secret {{ include "lapilli.webhookTokenSecret" . }} -o jsonpath='{.data.token}' | base64 -d \
       | kubectl -n <alertmanager-namespace> create secret generic lapilli-webhook-token --from-file=token=/dev/stdin

   (kube-prometheus-stack: list it under alertmanager.alertmanagerSpec.secrets.)
{{- if not .Values.webhook.auth.existingSecret }}
   GitOps note: tools that render with `helm template` (e.g. Argo CD) can't keep the
   generated token stable; create your own Secret (key `token`, ≥ 32 chars) and set
   webhook.auth.existingSecret.
{{- end }}
{{- else }}

   WARNING: webhook.auth.enabled=false: anything that can reach the Service can trigger captures.
{{- end }}

   A receiver on its own does nothing: Alertmanager needs a route that reaches it.

     route:
       routes:
         - receiver: lapilli
           continue: true                 # READ THIS ONE
           matchers:
             - alertname =~ "KubePodCrashLooping|KubeContainerWaiting|KubePodNotReady"

   `continue: true` is not optional. Without it this route consumes the alert and your paging
   route never sees it — Lapilli would start recording incidents by taking them away from the
   people who answer them. Put the route before your catch-all, with `continue: true`, so the
   alert goes to both.

   Match on rules that name a POD. Lapilli records a pod's incident window, so a node- or
   cluster-level rule (KubeNodeNotReady and friends) produces no capture at all: those alerts are
   counted in lapilli_alerts_dropped_total{reason="no-pod"} and the LapilliAlertsWithoutPod rule
   fires, which is the signal that a route's matchers are wider than Lapilli can use.

   Alertmanager's routing is the ONLY filter. Lapilli captures every firing alert it is sent, up
   to webhook.maxCapturesPerPayload ({{ .Values.webhook.maxCapturesPerPayload }}) per payload.
